Web2-供应链与依赖安全

供应链投毒的主要攻击方式

  1. 依赖包投毒（最常见）
  • 恶意包发布：攻击者向包管理器（PyPI、npm、Maven等）上传恶意包
  • 相似包名：创建与流行包名称相似的包（typosquatting）
    • 如：requests → requrests、requets
  • 依赖劫持：接管已弃用但仍有用户的项目
  • 版本劫持：在正常包的新版本中注入恶意代码
  1. 构建过程投毒
  • CI/CD管道攻击：入侵构建服务器，在构建过程中注入恶意代码
  • 构建工具/脚本篡改：修改Makefile、build.sh等构建脚本
  • 编译器投毒：污染编译器或解释器
  1. 开发工具投毒
  • IDE插件：恶意VSCode、PyCharm插件
  • 代码编辑器扩展
  • 代码格式化工具（如prettier、black的恶意版本）
  1. 第三方服务投毒
  • CDN污染：攻击内容分发网络
  • 镜像源篡改：如PyPI镜像、Docker Hub镜像
  • 代码仓库攻击：GitHub、GitLab等被入侵

读取 hmac_key.txt，得到密钥：Bkns_Data_Security_2026_Key

在计算机编码（如 ASCII 或 UTF-8）中，一个普通的连字符 - 或数字如果发生位偏移，很容易变成类似的特殊符号。

通过对 audit_logs.bin 进行 Hex Dump 分析，我们可以观察到以下规律：

**文件头 ：**前 44 字节内容为：4c 4f 47 5f 46 49 4c 45 5f 56 32 2e 30 5f 45 4e 43 52 59 50 54 45 44 5f 49 4e 54 45 47 52 49 54 59 5f 50 52 4f 54 45 43 52 45 44 0a对应的 ASCII 为：LOG_FILE_V2.0_ENCRYPTED_INTEGRITY_PROTECTED\n。

**数据块 ：**紧接着头部之后，是整齐排列的日志块。通过观察 Log Entry 000:, Log Entry 001: 等标识符的起始位置，可以计算出两个条目之间的偏移量恰好为 160 字节。

块内布局：

Data (0-127 字节): 存储 ASCII 日志文本。不足 128 字节的部分使用空格 (0x20) 填充。

HMAC (128-159 字节): 存储 32 字节的哈希值。由于长度为 32 字节，基本可以断定使用的是 HMAC-SHA256。

这个“脱敏结果”只包含小写字母 a-z，看起来像是把 hex 字符集(0-9a-f) 映射到 26字母中的某16个，也可能还带了“换位/插入”之类。

Broken Gallery(CBC padding oracle攻击)

gen_token()

  • 作用：生成一个合法的“令牌”（Token）供用户参考。
  • 流程：
    1. 随机生成一个16字节的初始化向量（IV）。
    2. 将固定的SEED（b"******_fackseed_*****"）用PKCS#7标准填充到16字节的倍数。
    3. 使用固定的KEY，以CBC模式和上一步生成的IV，加密填充后的SEED。
    4. 将IV和密文拼接，并转换为十六进制字符串返回。
  • 输出示例：类似 2a5f3c... (16字节IV + 16字节密文)。

parse_token(hex_in)

  • 作用：解析用户输入的Token，并返回解密后的明文。
  • 流程与三种返回状态：
    1. 返回None：当输入长度不足或不是合法十六进制时，表示格式错误。
    2. 返回False：当解密后的明文填充（Padding）无效时。这是整个挑战的关键信号（Padding Oracle）。程序会用哭脸A_ERR提示你。
    3. 返回解密数据（bytes）：当填充有效，成功解密并去填充后。程序会根据该数据是否等于SEED，输出笑脸A_WIN或困惑脸A_UNK。
解密结果 返回
padding 错误 (x_x)
padding 正确 (o_O)
内容等于 SEED (^v^)

解密思路：

  1. 初始化连接：连接到服务器，读取banner，获取一个合法的初始Token（IV + C1）。
  2. 分解Token：将Token拆分成IV和密文块C1。
  3. 循环解密：对每个密文块Ck执行解密。
    • 解密第一个块：使用原始的IV作为Prev，没有前缀（prefix = b""）。
    • 解密后续块：使用前一个密文块Ck-1作为Prev，前缀是IV和前面所有的密文块（prefix = iv + C1 + ... + Ck-2）。这样做是为了在构造攻击Token时，保持服务器解密时上下文的一致性。
  4. 拼接与去填充：将所有解密出的明文块拼接，然后使用pkcs7_strip函数去除PKCS#7填充，得到原始的SEED。
  5. 提交并获取Flag：通过submit_seed函数选择菜单选项“2”，输入解密出的SEED，服务器验证通过后即返回FLAG。

Trinity Masquerade(RSA参数恢复与解密)

公钥N由三个素数p, q, r相乘得到（标准RSA是两个素数），并给出了一个提示 H = p*q + r

目标得先恢复r

从H和N推导出r：已知：

  • N = p * q * r
  • H = p * q + r

设 X = p * q，则：

  • N = X * r
  • H = X + r

由 H = X + r 得 X = H - r，代入 N = X * r：
N = (H - r) * r = H*r - r²

整理得到关于r的一元二次方程：
r² - H*r + N = 0

解这个方程：
r = [H ± sqrt(H² - 4N)] / 2

由于 r 是一个素数（正数），且 X = p*q 远大于 r（因为p, q, r都是512位，X约为1024位），所以 H = X + r ≈ X，因此 H² >> 4N。取减号的那个解：
r = (H - sqrt(H² - 4N)) // 2
