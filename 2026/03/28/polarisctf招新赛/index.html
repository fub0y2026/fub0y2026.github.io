题目分析

代码有900多行，是ts

大致解释一下

  • 运行环境：Bun (支持原生 SQLite 模块)
  • 数据库：SQLite，存储能力快照、发布运行记录和挑战码
  • 认证：基于 HMAC-SHA256 的 Token 机制（类似 JWT）
  • 角色：guest（访客）和 maintainer（维护者）

认证系统：

  • 使用 HMAC-SHA256 签名，不同角色使用不同密钥
  • Token 格式：base64url(canonicalJSON).signature
  • 自定义的 canonicalize 函数确保签名一致性

能力快照管理:

数据库里有张表 capability_snapshots，每次会话行为都会往里写“能力快照”。

  • 作用：记录每个会话的能力状态
  • 特性：
    • 按时间戳排序，最新的生效
    • role 决定操作权限（guest/maintainer）,如果 role 是 NULL，就当成 'maintainer'
    • lane 决定工作流通道（public/release）,如果 lane 是 NULL，就当成 'release'

服务真正判断你有没有 release 权限，不是直接看 token 里的 claims.role，而是看 这个 sid 最新的一条 capability 快照。

表达式执行引擎:

这是服务的核心功能，允许执行受限的 JavaScript 表达式

  • 黑名单过滤危险 token（process, eval, child_process 等）
  • 表达式长度限制 1800 字符
  • 输出深度限制和截断
  • 使用 Function 构造函数创建沙箱
API 方法 权限 功能
/ GET 公开 帮助页面
/api/auth/guest POST 公开 获取 guest token
/api/session/self GET 任何 查看当前会话信息
/api/caps/sync POST guest 批量同步能力快照
/api/release/challenge POST maintainer+guest 获取发布挑战码
/api/release/execute POST maintainer 执行表达式
/api/release/claim POST maintainer+guest 提交证明获取 flag

  • cap.role === 'maintainer'
  • cap.lane === 'release'

要求 token 仍然是 guest，但 effective capability 必须是 maintainer/release。

解题思路

整条链分两段：

  1. 先提权到 effective maintainer/release
  2. 再想办法得到 RUNNER_KEY 或直接得到 FLAG_VALUE

第一步：拿 guest token

  • 请求POST /api/auth/guest,

  • 返回里有：

    • token
    • claims.sid

    后面所有操作都带这个 token。

第二步：利用 /api/caps/sync 制造“空 capability”

目标：让当前 sid 最新的一条 capability 快照里：

  • role = NULL
  • lane = NULL

因为这样 getEffectiveCapability() 读出来时就会自动变成：

  • role = maintainer
  • lane = release

WAF 绕过与读取

尝试调用 _0x72656164 (read) 读 /flag。这里遇到几个坑：

  • 代码里不能出现 readFile 这种名字，也不能直接出现 “/flag” 字符串，否则报 Security Policy Violation。
  • C++ 原生接 口处理 JS 字符串直接传入可能报错。

绕过方法：

  1. 变量名混淆为单字母 f。
  2. 路径转为 Uint8Array ASCII 数组传入，/flag 的 ASCII 码为 [47, 102, 108, 97, 103]，绕过字符串 WAF，且符合底层内存接口规范。
