弱 PRNG 预测 admin 密码

详细可以看：PRNG漏洞逆出admin密码 - DeepSeek

注册一个用户会生成一个随机16位的密码，登录时必须用这个随机16位的密码登录，注册admin发现已存在，猜测需通过密码生成过程反推出admin的密码

PRNG 的特点是：

  1. 确定性：只要种子相同，生成的整个数字序列就是完全相同的。
  2. 周期性：由于状态空间有限，生成的数字序列最终会重复。
密码的生成过程

生成原始密码

这一步调用了 RandomService 类中的 nextRandom() 方法，该方法会使用 PseudoRandomGenerator 来生成一个新的随机数。该随机数 plainPassword 是一个 64 位的长整型数（long）。这个数字将作为密码的原始值。

格式化密码

为了确保生成的密码符合系统的要求，plainPassword 通过 String.format() 方法被格式化成一个 16 位的字符串。格式化的过程包括以下两步：

  • 取 plainPassword 的后 16 位数字：plainPassword % 10000000000000000L。
  • 将该数字格式化为一个 16 位的数字字符串。

例如，若 plainPassword % 10000000000000000L 的结果是 1234567890123456，则最终的密码字符串将是 "1234567890123456"。

密码hash处理

在这一步，生成的明文密码 passwordStr 会通过 RandomService 的 encodePassword() 方法进行哈希处理。该方法使用了 BCryptPasswordEncoder 来加密密码：

BCryptPasswordEncoder 是 Spring Security 提供的加密工具，它采用 bcrypt 算法将密码进行加密，确保密码的安全性。通过这种方

式，即使数据库中的密码被泄露，也无法直接使用，因为 bcrypt 的加密是不可逆的。

PRNG 状态泄露

PRNG (Pseudo-Random Number Generator) 是一种通过数学算法生成伪随机数的机制。伪随机数并不是真正随机的，而是依赖于初始状态（种子值）和算法来生成一系列看似随机的数。

例如该题中：

PRNG 使用了 48 位的线性反馈移位寄存器 (LFSR)，这是一种常见的 PRNG 实现方式。LFSR 基于特定的移位和反馈规则生成新的数值

关键特点：

  • 状态空间：48 bit
  • 可逆
  • 每次 next() 更新一次状态

PRNG 初始化顺序:系统启动后 PRNG 调用顺序为：

初始化阶段：系统启动时，state 会通过 next() 函数更新 9 次。这里的 state 是伪随机数生成器的初始状态，之后每调用一次 next()，状态就会变化一次。

生成密码：state 的第 10 次更新会产生 admin 密码。之后，第 11 至第 15 次更新会分别产生 5 个用户密码（user1 至 user5）。每个用户的密码都是 next() 生成的随机数。

新注册用户：当一个新用户注册时，系统会根据当前的 PRNG 状态生成一个密码，而这个状态是从 admin 密码的状态向前推进了 6 步。

原：

逆向时，我们不能直接从 old_state 推算出 new_state，但可以通过如下公式逆向计算：

其中 bit0 是 state 的最低位，可以是 0 或 1，因此每一步都会有两个可能的候选值。

通过逆向 6 步，你可以得到 64 个可能的候选状态，每个状态对应一个可能的 admin 密码。逆向计算的步骤如下：

  1. 已知的 admin 密码：系统会返回一个 16 位数字的密码，这个密码来自于 PRNG 的某一时刻。我们需要通过该密码反推前 6 步的 PRNG 状态。
  2. 逆向每一步：每一次逆向计算都会产生两个可能的 old_state（因为最低位 bit0 可能是 0 或 1）。因此，每次逆向时都有两个候选状态。
  3. 生成候选状态：逆向 6 步之后，将获得 64 个候选的 state，每个候选状态都对应一个可能的 admin 密码。

为了验证这些候选状态中的正确性，需要将每个候选状态前推 6 步，看看是否能够得到已知的 admin 密码。

  • 前推 6 步：从每个候选的状态出发，调用 next() 函数 6 次，得到一个新的密码。
  • 匹配已知密码：如果生成的密码与已知的 admin 密码匹配，那么这个候选状态就是正确的，反向推算的密码就是 admin 密码。
