ez_include_revenge(data伪协议解析差异)

考点：file_get_content和include对data伪协议有检测差异

不能用点和php伪协议，试了一下data伪协议，allow_url_include=0直接限制死了远程包含都不行

那就只能结合file_put_contents('profile',print_r($_SERVER,true));来解题了

非预期

非预期原因：

file_gets_contents只会在工作目录找

mkdir无法递归创建目录除非使用-p参数。那么前面的

就是没用的，这点其实在报错中也可以体现！然后如果xff为空profile就写在html目录下，chdir(‘..’)到www，所以此时工作目录是www！脚本目录是html！

file_gets_contents在工作目录肯定找不到profile，但是include会去脚本目录找，所以直接绕过。

也就是说我们把profile写到了脚本目录去（/var/www/html/profile），然后工作目录不是脚本目录的时候就可以绕过！利用的是这两个函数处理的差异性！

预期

也是考file_get_content和include对伪协议有检测差异

对于data:,10086这样的，file_get_contents会把它当作伪协议，结果就是10086，而include则会将它当成文件名。

因此传入data:,/profile，file_get_contents结果是/profile通过waf，include则会在data:,目录下找profile文件，对应的我们操作xff即可：

取证大师1

顺便把取证做了吧

找日志，但发现/var/log/auth.log里没有有用的

发现老日志在/var/log/auth.log.1

  • 使用 awk 处理每一行
  • for(i=1;i<=NF;i++) - 遍历该行的所有字段
  • if($i ~ /[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+/) - 如果字段匹配IP地址格式（如 192.168.1.1）
  • print $(i) - 打印出匹配的IP地址

sort

  • 对提取出的IP地址进行排序（为下一步的 uniq -c 做准备）

uniq -c

  • 统计并计数重复的IP地址
  • -c 参数会在每行前面显示该IP出现的次数

sort -nr

  • -n - 按数值排序
  • -r - 反向排序（从大到小）
  • 这样攻击次数最多的IP会排在最前面
