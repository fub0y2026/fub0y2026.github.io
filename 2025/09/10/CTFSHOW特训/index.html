  • 只要 write 里没有 .jsp 或 .xml，就允许写文件

我读题解的时候还在想为什么可以反序列化，这里没有readObject，后面才知道这是Tomcat-Session反序列化

知识点

CVE-2020-9484

要求：

  1. tomcat必须启用session持久化功能FileStore
  2. tomcat/lib或者WEB-INF/lib目录下的依赖存在可用的gadget
  3. 在服务器上存在已知路径文件内容可控

当开启了session持久化功能FileStore的时候：会把JSESSIONID的名称作为SESSION文件名的一部分进行读取之后反序列化（可以联想PHP的SESSION反序列化）

比如JSESSIONID=…/…/…/…/…/…/…/…/feng，那么就会读取/xxxxxx/…/…/…/…/…/…/…/…/feng.session的内容并反序列化。如果目标系统中存在可用的Gadget，就可以反序列化rce。（比如tomcat/lib或者WEB-INF/lib）下面。

CLI SAPI 提供了一个内置的Web服务器。

这个内置的Web服务器主要用于本地开发使用，不可用于线上产品环境。

URI请求会被发送到PHP所在的的工作目录（Working Directory）进行处理，除非你使用了-t参数来自定义不同的目录。

如果请求未指定执行哪个PHP文件，则默认执行目录内的index.php 或者 index.html。如果这两个文件都不存在，服务器会返回404错误。

当你在命令行启动这个Web Server时，如果指定了一个PHP文件，则这个文件会作为一个“路由”脚本，意味着每次请求都会先执行这个脚本。如果这个脚本返回 false ，那么直接返回请求的文件（例如请求静态文件不作任何处理）。否则会把输出返回到浏览器。

system() 调用会在宿主系统上执行一条 shell 命令：先 sleep 5（等待 5 秒），然后启动 PHP 内置的 web 服务器 php -S：

  • php -S 0.0.0.0:80：在所有网卡（0.0.0.0）上监听 80 端口；端口 80 是 HTTP 默认端口。
  • -t /tmp/：把 /tmp/ 目录作为 web 根目录（DocumentRoot）。因此访问该服务器的根路径会处理 /tmp/index.php，从而使上面写入的 webshell 可通过 HTTP 访问并执行 $_POST['a'] 的内容

第二次反序列化执行$this->params=serialize(new settings()); 时unserialize() 看到序列化里有 O:<len>:"settings":...，此时 运行时并没有定义 settings 类，所以 PHP 会触发“缺类回调”（即 unserialize_callback_func 所指定的函数），并把缺失的类名（这里是 "settings"）作为参数传给回调。

这里作为第一个参数即类名：settings，第二个参数即文件后缀名未指定，默认使用inc

那么最终的结果就是由于settings类不存在，就会包含settings.inc文件，里面写入了恶意代码
