L3HCTF2024-intractable_problem（栈帧逃逸）

oj.py:

web.py:

后端有一个 oj.py 模板文件，里面有占位符 <<codehere>>

用户提交的 code 会被插进去，形成一个新的 Python 程序

同时把字符串 "Correct" / "Wrong" 替换成随机字符串，防止用户直接硬编码输出绕过

把拼好的 Python 写到 upload/xxxx.py。

用 subprocess.run() 调用 python3 来执行，限制 5 秒。

执行完删除代码文件。

如果用户代码最后输出以 correctstr+"!" 结尾，就认为正确，返回 "Correct! flag is ..."。

否则返回 "Wrong!" 或 "Timeout!"。

对输入做了一些过滤，过滤掉了双下划线，防止我们通过继承链得到builtins

{"__builtins__": None} 置空了__builtins__。

这里的if条件是：首先p和q都得大于100000，其次就是p和q的积为int(“69…97863”)

按照题目要求，如果通过算法在要求的5秒实现基本上是不可能的，但是我们可以通过沙箱外的globals的__builtins__字段去修改int函数，实现绕过if语句，这道题的解题思路就是通过栈帧对象逃逸出沙箱从而获取到沙箱外的globals。

又因为设置了{"__builtins__": None} ，所以不能直接通过next()函数去获取到栈帧，但可以通过for语句去获取

可以注意到在判断答案是否正确时的globals与沙箱内获取到的globals相同，因此可以想办法破坏判断的过程绕过答案校验。一个可行的方法是替换掉int函数，使python在校验时使用我们给出的数据进行校验，payload如下：

调用帧：

a.gi_frame->生成器当前正在运行的 frame 对象

a.gi_frame.f_back->factorization的执行帧

a.gi_frame.f_back.f_back->通常是外部判题器 exec() 执行时的帧

a=[x for x in a][0]把 Frame C 取出来，保存到变量 a，现在 a 已经是 Frame C

a.f_back → Frame D（再上一层， judge 函数）

a.f_back.f_back->Frame E（顶层，模块级别 __main__ 的执行帧）

a.f_back.f_back.f_globals → Frame E 的全局变量字典，相当于 globals()

当然，这里也可以非预期：闭合就行

第九届中国海洋大学信息安全竞赛 菜狗工具#2（栈帧逃逸）

new_builtins 是从当前 __builtins__（模块）里拷贝除了黑名单以外的所有内置符号，形成一个新的内置字典。之后会把这个字典作为 exec 的 __builtins__ 使用。

定义 wrap_print：把 file 强制设置为 out，然后调用内置 print（注意这里的 print 是外层环境的 print，但随后 new_builtins["print"] 被替换为 wrap_print 本身，使得被执行脚本中的 print 会把输出写到 out）。

接script，用exec(script, {"__builtins__": new_builtins})执行

flag在源码中，但是源码被删除，没有 /proc目录

这里把__builtins__模块中的恶意模块删去了，我们用栈帧逃逸重新获取__builtins__

要获得被覆写的 flag 内容只剩一个地方可以找，就是依靠 python 解析自身进程的内存

cpython 的实现中暴露了获取 python 栈帧的方法

而每个栈帧都会保存当时的 py 字节码和记录自身上一层的栈帧

而对 flag 的赋值的字节码肯定存在于某个栈帧中，我们只需要从当前栈帧向上找就行了

法一

利用 ctypes模块的指针，将flag地址周围的值读一下，实现一个从内存读源码

因为真正的flag在覆盖的flag之前，所以读到假的flag的地址后，往前读取即可

这里用了char 指针，读出来的是一个字符串

最细节的是每次位移8的倍数。（可以自行对比任意两个变量的地址，可以发现它们的差值都是8的倍数）

法二

用load_module() 方法动态加载 Python 的内置模块 gc（垃圾回收模块）

gc.get_objects() 会返回当前 Python 解释器里所有被 GC 管理的对象列表。
这几乎包含了整个运行时的对象（所有字符串、类、函数、frame、dict 等）。
