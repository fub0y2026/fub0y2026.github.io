passwordless

注册就是填一个邮箱，但没用实现发送邮箱验证码功能

登录也不知道密码

源码：

看到/user路由，

normalizeEmail 可能是来自 validator 库，用来标准化邮箱（去掉大小写、点号等）

如果邮箱超过 64 个字符，就提示错误，拒绝注册。

注册电子邮件地址时，密码是用户邮箱 + 16字节随机值（十六进制）

bcrypt.hash(initialPassword, 10, function (err, hash)
用 bcrypt（工作因子 10）对初始密码进行哈希。

这里就有一个逻辑漏洞：

Bcrypt 哈希密钥的长度限制为 72 个字符，如果电子邮件地址足够长，附加的随机16字节密钥将不会包含在哈希中。绕过长度检查可能会滥用电子邮件规范化（有关规范化电子邮件包的更多详细信息），例如提供 72 个字符长的 gmail 地址 tast+278901234567890123456789012345678901234567890123456789022@gmail.com 。

在 Gmail（以及很多邮箱服务商）中：

  • 本地部分（@ 前面）可以写成 username+anything@gmail.com。
  • 邮件仍然会投递到 username@gmail.com，+anything 会被当作标签，自动忽略。

normalizeEmail去掉 + 后面的所有字符

而密码则依旧适用的是normalizeEmail前的邮箱

使用此类电子邮件地址注册，然后在登录时邮箱和密码为tast@gmail.com/tast+278901234567890123456789012345678901234567890123456789022@gmail.com
