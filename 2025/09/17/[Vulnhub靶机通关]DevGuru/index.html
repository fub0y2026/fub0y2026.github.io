通过gitea数据库登录后台

依旧www-data权限

这里我们采用sudo提权

开局就被拒，呜呜呜

权限太太低了，想办法先提高一点权限

用PEASS-ng工具扫描（用于扫描敏感文件），扫出来一个备份文件：
/var/backups/app.ini.bak

这里找到一个gitea数据库账号密码

想到我们之前8585端口的页面不就是gitea吗，这里猜测就是8585端口的服务

我们试着能不能得到8585端口服务shell，可能权限比80端口权限高

进入数据库

我们编辑这个用户的时候看到了加密方式，pbkdf2

在GitHub找到Gitea源码，在该存储库下搜索关键字"pbkdf2"，其使用pbkdf2算法进行加密，生成长度为50的hash值，迭代次数为10000，Salt就是之前的Bop8nwtUiM。

Gitea源码地址：https://github.com/search?q=repo%3Ago-gitea%2Fgitea+pbkdf2&type=code

使用在线网站生成pbkdf2密码，填写已知信息Salt、明文、迭代次数、生成的hash长度。

替换Gitea管理员frank的密码hash值，成功登录8585端口的Gitea。

或者

我们可以修改frank用户的加密方式，重新搞个密码

修改加密方式为：Bcrypt

密码改为：123456

用账号密码登录8585端口的后端frank/123456

成功登录

法一 MSF

MSF搜索Gitea相关漏洞发现CVE-2020-14144，该漏洞需要认证才可使用，我们现在已满足条件，设置好options然后run，成功拿下frank的普通用户权限。

成功getshell

法二 复现漏洞

直接复现该漏洞也行，进入项目 >> Settings >> Git Hooks >> Update 写上bash反弹命令保存，Kali这边nc监听，更新项目任意文件即可收到会话。
