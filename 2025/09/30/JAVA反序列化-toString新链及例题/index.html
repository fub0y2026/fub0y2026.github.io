这里学**TextAndMnemonicHashMap链**（JDK8环境，JDK17环境的Hashtable#readObject无法利用）

TextAndMnemonicHashMap类是UIDefaults类的一个私有内部类

在UIDefaults的子类TextAndMnemonicHashMap类中，存在get方法能够接收一个key参数，当在HashMap中通过get方法取这个key最终结果为空时，就会触发key.toString()从而触发toString()方法。

现在找一个能触发get方法的：
AbstractMap#equals

在遍历键值对的时候，当键值对遍历时，其中的value为空，就会触发m.get()方法。

然后找一个readobject方法中调用了equals方法的类，熟知的有hashtable的reconstitutionPut方法还有hashmap的putval方法，先来看hashtable

看到会掉用reconstitutionPut方法，而该方法中调用了equals方法所以后面在拼接jackson就可以闭环。

这里解释下为什么javax.swing.UIDefaults$TextAndMnemonicHashMap的键能够触发AbstractMap的equals方法，因为TextAndMnemonicHashMap继承于HashMap，HashMap继承于AbstractMap并且HashMap没有实现equals方法，最终就是找到AbstractMap中的方法。

getGift()方法用反射拿到 URLClassLoader.addURL(URL) 方法，调用 addURL 动态添加 jar 包或 class 路径

也就是传gift参数进去动态加载jar包，但gift 把http和file ban 了，这里学到了用jar协议来绕开并且远程加载jar包即可

解题思路

有反序列化点，有远程加载jar包，且方法名为getGift()，可以通过toString()方法调用

参考大佬解题思路：2024羊城杯ezJava EventListenerList新链反序列化-先知社区

  1. 本地构造一个Calc类，让这个类的static、readObject方法里放上反弹shell的代码
  2. Shiro漏洞绕过登录到后台
  3. 通过/user/ser接口反序列化触发User#getGift方法，把远程jar包路径添加到URLClassLoader里
  4. 再次通过/user/ser接口触发Calc类的反序列化，此时服务器默认不存在Calc类，但是会去远程jar包里找，最终初始化Calc类完成反弹shell

(这里User类中的getGift 方法只是把远程路径去加载进去，如果你不触发这里那么是不会去请求远程类的，另外URLClassLoader 是先会从本地加载类，找不到才会加载远程类，所以你的恶意类不能带包名，否则它就会当成是你本地的类，也不会去远程加载了)
