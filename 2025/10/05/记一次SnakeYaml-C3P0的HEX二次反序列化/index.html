一次反序列化链分析

C3P0有条hex链子：

WrapperConnectionPoolDataSource：Hex 二次反序列化

简单解释一下为什么 SnakeYaml 可以触发 Hex 二次反序列化这条链子：首先 SnakeYaml 在反序列化的时候会根据 yaml 中的类属性描述进行相关 setter 方法并调用

WrapperConnectionPoolDataSourceBase 是 WrapperConnectionPoolDataSource的父类

com.mchange.v2.c3p0.impl.WrapperConnectionPoolDataSourceBase#setUserOverridesAsString在 snakeyaml 反序列化的时候会被调用

在fastjson反序列化漏洞中，这个链子的使用方法为

@type
这是 Fastjson / Jackson 等反序列化框架的多态特性，用来指定要反序列化成的 Java 类。

a 部分
这里把 "val" 指向 com.mchange.v2.c3p0.WrapperConnectionPoolDataSource，其实是为了让 Fastjson 先加载这个类（有时会触发类初始化）。

b 部分
这里直接构造了一个 WrapperConnectionPoolDataSource 实例，并设置了它的 userOverridesAsString 属性。

userOverridesAsString 的作用

在 C3P0 里，这个字段是用来加载用户自定义配置的，它的值会被解析：

  • 如果以 HexAsciiSerializedMap: 开头，C3P0 会把后面的十六进制字符串反序列化成一个 Map 对象。
  • 这个反序列化是用 Java 原生反序列化（ObjectInputStream.readObject()）实现的。

这个Hex就是一个经过十六进制编码的 Java 序列化数据流（可以放入CC链等其他利用链的HEX编码）
当反序列化到 WrapperConnectionPoolDataSource 时，C3P0 会自动去解码并反序列化这个数据，导致二次反序列化漏洞。

流程是：

  1. Fastjson 先反序列化 JSON → 创建 WrapperConnectionPoolDataSource 对象。
  2. Fastjson 在赋值 userOverridesAsString 时并不会立即执行反序列化，只是存进去。
  3. 在 C3P0 的某些方法调用（如 toString() / equals() / 初始化连接池时），会去解析 userOverridesAsString。
  4. C3P0 内部调用 Java 反序列化 → 触发 <payload> 中的 gadget 链 → RCE。

而在SnakeYaml反序列化漏洞中，我们像这样的一次反序列化payload可以表示为

道理都是一样的，这里是 通过SnakeYaml 反序列化触发java原生反序列化

总结：

当 yaml.load(poc) 执行时：

  • SnakeYAML 会根据 !<tag:...> 标签实例化 WrapperConnectionPoolDataSource。
  • 给它的 userOverridesAsString 属性赋值 "HexAsciiSerializedMap:..."。

在 WrapperConnectionPoolDataSource#setUserOverridesAsString() 内部，C3P0 会调用 ObjectInputStream.readObject() 去反序列化 Hex 中的数据，这就是 第一次进入 Java 原生反序列化。
