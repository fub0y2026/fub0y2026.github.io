hessian2反序列化流程简单分析

以防忘记了，再来理一遍，这里直接扒大佬的（我是躺赢狗）

拿Map类型的类来进行序列化，因为hessian2只有在tag为72，也就是第一个反序列化的类为Map类型时才会走到MapDeserializer#readMap从而触发map.put方法。

可以发现，读取到的第一个字节tag为72，也就是Map类型的类，跟到case中。

72的case就实现了一个方法，也就是readMap方法，步入。

这里会新建一个MapDeserializer，默认反序列化成 HashMap，并调用readMap。

这里会将序列化数据反序列化为一个map类，并且其中调用了map.put进行赋值操作，正是map.put这个方法导致了后续的反序列化问题。

具体细节可以参考这个佬写的文章https://xz.aliyun.com/news/17603

HashMap->AudioFileFormat->toString

首先还是构造HashMap->equals，代码如下：

然后走到AudioFileFormat$Type#equals。

如图所示，AudioFileFormat$Type#equals中会调用任意toString从而触发Jackson或fastjson的toString方法。

AudioFileFormat$Type 是作为 HashMap.equals() 里的“被比较 key”，在反序列化过程中被隐式调用了 Type.equals()，而这个 equals() 里调用了 toString()，从而触发了 JSONArray.toString() → ServerManagerImpl.getActiveServers()

因此完整代码如下：

ConcurrentHashMap->AudioFileFormat->toString

这个和上面那个不同在于：

上一个是 HashMap.equals → key.equals → AudioFileFormat$Type.equals → toString
这个是 ConcurrentHashMap.readObject → Node.equals → MapEntry.equals → key.equals → toString
